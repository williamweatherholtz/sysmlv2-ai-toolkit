# decision-surfacing — lead with the link, don't bury the ask

Deploys `.engine/processes/decision-surfacing.sysml` (D0269). A decision the human cannot find is
not a decision they have been asked to make.

## The failure this ends

I reported open decisions accurately, in prose, at the **end** of long turns — several times in one
session. Each report was true and each was buried under the work that produced it. Their words:
*"Don't bury it under past messages."*

## Procedure

1. **Detect.** Something is pending when the work cannot honestly continue without their judgment,
   or continued under an assumption they never confirmed: a proposed Need/Decision with no
   acceptance, a fork where the other side is defensible, an accepted risk they haven't seen, a
   priority order I chose. **Not** pending: anything I decided and can defend, or a question I can
   answer by reading the model. *Manufacturing a decision to have something to surface is worse than
   burying one.*
2. **Render.** Deploy `exec-summary` against the se-templates instance — one tab per decision, each
   with stake, steelmanned options, honest costs, a recommendation, and what would change it. Run
   the browser suite; its word budgets have rejected my drafts three times for good reason.
3. **Ground each tab so it can be judged independently.** The failure this ends, in their words:
   *"I get some semblance of 'we need Need1 & Need2 judged. WHAT DECIDES IT: picking which ones are
   good.'"* That is circular. Every tab carries, **inline**:
   - **the item itself** — the actual statement, quoted. A decision needing another file opened has
     not been surfaced.
   - **what accepting binds** — what it legitimises, what it forecloses. A Need is a contract future
     work will cite.
   - **the specific fork** — the contested clause against its alternative, in their words. Never
     "good vs bad".
   - **the evidence** — what is already TRUE in the model vs. what is my assumption, labelled apart.
   - **what I do with each answer** — the concrete next action per option.

   **Test for "What decides it":** it must name an *observable*, or a value only they hold. If it can
   be answered by reading the model, I haven't finished my work — answer it myself.
4. **Publish as an artifact** for a durable URL. **Republish the same file path** to update in
   place — a decision page that forks into several links is buried again, differently.
5. **Lead with it.** The URL goes in the **first lines** of the response, with a one-line name per
   pending item. The report of what was done comes *after*.
6. **Carry it.** Re-surface every turn while anything is pending. Silence is not consent — it
   usually means the message scrolled past. A decision leaves the page only when answered or when I
   **state** that I'm withdrawing it. One that quietly stops being mentioned was decided by default,
   by me, invisibly.

## Removal path

Delete this skill + registry + the process file. Nothing else depends on it; the exec-summary skill
and template are independent and stay.
